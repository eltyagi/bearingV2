Light FDE as a service

Workspace template for customer engagements. Bearing | GitHub Copilot App workflow

Proposed This site is a static template. It is not published, has no access control configured, and does not run any workflow. Only repository discovery (/onboard-repo) is built. Surveys, response synthesis and workshop assembly are not built.

The idea

Customers now ask for AI outcomes and impact. A light forward-deployed engineer helps field teams discover the customer's situation, survey for fine-grained requirements and turn them into a workshop. Copilot does the first pass; a named person approves each gate. It does not replace forward-deployed engineers, service owners or facilitators.

Who sees which customer

Proposed GitHub Pages access control is set for the whole site, not per page or per person. A privately published site is open only to people with read access to the repository it is published from, and publishing privately needs an organization on GitHub Enterprise Cloud with a private or internal repository (GitHub docs, checked 2026-10-07). So "different customers for different people" means one repository, and one private site, per customer. Grant read access by team to the people on that engagement.

Design choiceWhy
One repository and site per customerSite access follows repository read access, so a customer's people-list is the repository's team list.
Synthetic or approved content onlyDo not put customer data here without explicit authorization. This template repository stays free of it.
Page per stage, gate log per pageEach stage records the approver and date, so nothing moves on without a named person.
